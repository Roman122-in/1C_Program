# Описание задачи: Производство хозяйственного ведра 7л

## 1. Материал (Сырье)
 **Название в базе данных:** Поліпропілен вторинний (фрукт. ящик), гранула
 **Тип материала:** Вторичный полипропилен (PP, сорт — литьевой).
**Описание:** Сырье поставляется в виде мелких гранул черного или темно-серого цвета. Материал получают путем переработки чистых производственных и бытовых отходов (пластиковых фруктовых ящиков).
 **Преимущества выбора:**
 
 **Низкая стоимость (**33 ₴/кг** против 800 ₴/кг за первичный пластик).**
  1. Высокая прочность и отличная текучесть при расплавлении в ТПА.
  2.  Идеально подходит для производства непищевых, износостойких хозяйственных товаров.
  3. Экономия на красителях (гранула уже имеет ровный черный цвет).

---

## 2. Готовое изделие (Продукция)
1. **Название в базе данных:** Відро господарсько-будівельне 7л (чорне)
2.  **Тип товара:** Готовая продукция (изделие из пластмасс).
3.  **Описание:** Прочное, эластичное хозяйственное ведро объемом 7 литров с литой пластиковой ручкой. Цвет — черный, матовый или полуглянцевый. Предназначено для садово-огородных, бытовых и строительных работ (перенос земли, воды, замес штукатурных и строительных растворов).
4. **Технический вес изделия:** **350 грамм** (0.35 кг).

## 6. Реализация раздела "Производство"


Предположим, у нас есть логи со станков, имеющие такой вид:
DATE,TIME,COUNT,ActCntCyc,ActTmpBrlZn[1,1],ActStrCsh[1],ActStrXfr[1],ActStrPlst[1]
20140424,09:14:19,1,8879,0.0,2.33,29.66,32.00
20140424,09:14:28,2,8880,0.0,2.33,29.67,32.00
20140424,09:14:36,3,8881,0.0,2.32,29.67,32.00
20140424,09:14:45,4,8882,0.0,2.33,29.68,32.00
20140424,09:14:53,5,8883,0.0,2.34,29.67,32.00

Где, 

###  Описание полей лог-файла станка:

 **`DATE`** — дата фиксации строки лога (в формате `ГГГГММДД`).
 **`TIME`** — время фиксации строки лога (в формате `ЧЧ:ММ:СС`).
 **`COUNT`** — порядковый номер записи (сквозной счетчик строк в лог-файле).
 **`ActCntCyc`** (*Actual Cycle Count*) — фактический счетчик циклов работы станка (увеличивается с каждой законченной деталью).
 **`ActTmpBrlZn[1,1]`** (*Actual Barrel Zone Temperature*) — фактическая температура в первой зоне нагрева цилиндра литьевой машины.
 **`ActStrCsh[1]`** (*Actual Cushion Stroke*) — фактическая остаточная подушка впрыска (положение шнека в миллиметрах в момент окончания впрыска).
 **`ActStrXfr[1]`** (*Actual Transfer Stroke*) — фактическая точка переключения (позиция шнека, при которой машина переходит с фазы впрыска на фазу выдержки под давлением).
 **`ActStrPlst[1]`** (*Actual Plasticizing Stroke*) — фактический ход пластикации (конечная позиция шнека после набора дозы расплавленного пластика перед следующим циклом).

## 7. Логика работы с оборудованием и автозаполнение

В зависимости от типа оборудования сбор данных для расчета износа и работы происходит по-разному.

###  Источники данных по оборудованию
Для сушилки и дробилки технические логи могут отсутствовать (так как на таком оборудовании они часто не предусмотрены). В этом случае износ рассчитывается на основе **Рапорта смены** (по количеству произведенных за сегодня килограммов продукции).

---

###  Справочник «Оборудование»
В подсистеме «Производство» добавляется справочник оборудования со следующими значениями:
 **Аппарат для литья**
 **Дробилка**
 **Сушилка**

---

###  Кнопка «Автозаполнение» в производственных логах
Во вкладке **«Производственные логи»** добавляется кнопка **«Автозаполнение»**. 
> *Важное условие:* кнопка активна и может сработать **только тогда, когда выбран конкретный тип оборудования**.

#### Логика работы кнопки:
1. **Для аппарата для литья:**
    Происходит обработка поступающих производственных логов.
   Логи поступают в программу 1С в уже отсортированном виде (в виде готовой таблицы).

2. **Структура входящего лога для литья:**
    **`ActCntCyc`** (*Actual Cycle Count*) — счетчик циклов работы.
   **`DATE`** — дата фиксации строки лога (в формате `ГГГГММДД`).
   **`TIME`** — время фиксации строки лога (в формате `ЧЧ:ММ:СС`).
   **`COUNT`** — порядковый номер записи (сквозной счетчик строк в лог-файле).

Логика в том, чтобы при нажатии кнопки "Автозаполнение" происходил запрос
SELECT 
    MAX(ActCntCyc) - MIN(ActCntCyc) AS TotalCyclesDone
FROM machine_logs
WHERE DATE = '2026-08-12';


показывающий количество циклов за прошедший день. Таким образом, бухгалтер должен в течение дня заполнить значения за предыдущий день. Дата записи в документе всегда означает, что запись отражает положение дел за предыдущий рабочий день. Данная система не предназначена для начисления зарплаты, она нужна только для расчета себестоимости и износа оборудования. Если бухгалтер выбирает дробилку или сушилку происходит автозаполнение из документа Сменный рапорт, где отражено значение произведенных ведер из расчета  0.35 кг за штуку в сырье и количество брака, который на 90% возвращается на склад сырья. Количество брака считывать необходимо потому, что оно увеличивает время работы дробилки, составляя его основное время работы в принципе. Также количество произведенной продукции приблизительно соответствует времени работы сушилки, что влияет на ее износ.

## 9. Алгоритм работы кнопки «Автозаполнение» в документе «Производственные логи»

Кнопка «Автозаполнение» доступна в документе «Производственные логи», содержащем реквизиты:
**Дата** (стандартное поле ввода)
**Аппарат** (тип: `СправочникСсылка.Оборудование`)
**Количество** (числовое поле для записи результата)

###  Условия активации кнопки
Кнопка «Автозаполнение» должна быть активна и срабатывать **только тогда**, когда одновременно выполнены два условия:
1. Заполнено стандартное поле **Дата**.
2. Выбран конкретный **Аппарат** из справочника.

---

## 10. Логика работы кнопки «Автозаполнение» (Клиент-Сервер)

###  Проверка на клиенте
При нажатии кнопки **«Автозаполнение»** форма производит предварительную проверку обязательных полей. Кнопка сработает только в том случае, если заполнены:
 **Дата**
 **Аппарат** (выбран из справочника `СправочникСсылка.Оборудование`)

Если поля заполнены, данные передаются в серверную функцию **без контекста** (в серверный метод с ключевым словом `ПолеВызова` / `ВариантБезКонтекста`).

---

###  Обработка на сервере по типам аппаратов

Серверная функция анализирует название выбранного аппарата и выполняет соответствующий алгоритм:

1. **«Аппарат для литья»:**
   Считываются данные с сервера баз данных через SQL-запрос (или генерируется тестовое/расчетное значение, например, случайное число от **800 до 1000** циклов/единиц).

2. **«Дробилка»:**
   1. Выполняется поисковый запрос к документу **«Сменный Рапорт»** за **предыдущий день**.
   2.  Из табличной части **«Детали Смены»** суммируется поле `Брак Количество Шт` (количество брака в штуках).
   3. Полученное значение умножается на коэффициент **0.35**, чтобы перевести штуки брака в килограммы (учитывая, что масса одного изделия составляет 0.35 кг).

3. **«Сушилка»:**
   1. Выполняется поисковый запрос к документу **«Сменный Рапорт»** за **предыдущий день**.
   2. Из табличной части **«Детали Смены»** суммируется поле `Количество Сырья Кг`, отражающее общий объем израсходованного материала.

---

###  Запись результата
1. Полученное на сервере итоговое число возвращается обратно на клиент.
2. Значение записывается в реквизит **`Объект.Количество`**.
3. Документ автоматически помечается как измененный (модифицированность устанавливается в `Истина`), требуя сохранения пользователем.
